### 4.4 تدفق الحجز (من المنتج المعلن + واجهة الملف)

الزبون **لا يحمّل تطبيقاً ولا يُفرض عليه حساب**.

1. يفتح رابط الصالون أو السوق أو رابط الحجز الخاص.
2. يختار **خدمة** (مدة + سعر للعرض فقط).
3. يختار **موظفاً** (أو أي متاح) — لكل موظف تقويم وخدمات وساعات.
4. يختار **تاريخاً** ضمن أيام العمل (مثال موثّق: الاثنين–السبت 09:00–22:00، الأحد حتى 20:00).
5. يرى **فترات متاحة** محسوبة من مدة الخدمة + تعارضات التقويم.
6. يدخل **الاسم والهاتف**.
7. يؤكد. وضع الموافقة: **تلقائي AUTO** أو **يدوي MANUAL** حسب إعداد العمل.
8. إشعار واتساب للزبون + إشعار لصاحب العمل في التطبيق.
9. الدفع: **ليس عبر المنصة** — عند الحضور.
10. إلغاء/تعديل: حسب قواعد العمل؛ إن فُتح الرابط يمكن، وإلا التواصل مع الصالون. المقعد يُعاد فتحه فوراً عند الإلغاء.
11. تذكير واتساب قبل الموعد (من حصة الخطة). عند نفاد الحصة تتوقف التذكيرات الآلية ويبقى المراسلة اليدوية.

لا بوابة Stripe للزبون. لا OTP موثّق كشرط حجز للضيف (الهاتف للتواصل/التذكير). الحساب اختياري للزبون في السوق (أزرار دخول/عضوية في الترويسة).

### 4.5 مصادقة

- لغة الواجهة: دخول / عضوية.
- أعمال: التسجيل عبر التطبيق + تجربة 30 يوماً.
- خصوصية أندرويد: توكن FCM، حالة الاشتراك عبر RevenueCat.
- حذف الحساب: التطبيق (ملف → إعدادات → حذف) أو بريد.
- عمر 18+ أو بإشراف ولي أمر.
- ممنوع تعدد الحسابات لنفس الشخص/العمل.

لم تُرصد صفحة reset-password عامة منفصلة في HTML الثابت؛ التدفق مرتبط بالتطبيق/مودال.

### 4.6 لوحة الزبون

ليست كثيفة على الويب العام. السوق يعرض المفضلة/المواعيد إن وُجد حساب، لكن التشغيل اليومي لصاحب العمل **موبايل**. للتكييف العراقي: نوبو يبني منطقة زبون ويب كاملة (مواعيد، مفضلة، ملف) لأن الاستراتيجية «ويب أولاً».

### 4.7 تسجيل الشريك / للأعمال

لا بوابة ويب تشغيلية كاملة. المسار: `/indir.html` أو شارات المتاجر → إنشاء عمل في التطبيق → رابط حجز + موقع قالب. السوق فيه CTA «أضف عملك مجاناً».

### 4.8 مدوّنة، قانوني، تواصل

- مدوّنة ضخمة SEO (كيف يعمل النظام، واتساب vs أونلاين، no-show، أدلة قطاعات، مواقع جاهزة).

- شروط: وسيط تقني غير مسؤول عن جودة الخدمة، اشتراك المتجر، ملكية فكرية، حظر أنشطة غير قانونية، انقطاعات.

### 4.9 موبايل مقابل ديسكتوب واللغة
